= Editor presentation state

A window of the QML interface with a `stateKey` (`Ez.DialogWindow`) opens
where and as large as it was when last closed: `QmlHost` keeps its rectangle
in `window_states/qml/<name>` (`WorkspaceStore::dialogGeometry`). Other windows
open centered on the window they belong to. New windows only need a
`stateKey` to keep their place; anything else they remember goes through an
explicit settings key.

The main window (`MainWindow.qml`, `QmlShell`) keeps its geometry (as the
window `MainWindow`) and the layout of its docks (KDDockWidgets'
`LayoutSaver`). The workspace of each project,
`project_workspace/<SHA-256 of the project folder>` (`Workspace`,
`WorkspaceStore`), stores the dock layout, the map tabs in their order with each map's zoom, selected cell and
scrolling (`MapEditor`), the active map, the map tree's selection, expanded
nodes and scrolling, the palette's scrolling, and the drawing controls and
both tile brushes (`EditorState::editingState()`). The layout older
versions saved stays as it was.

The database window keeps the page and the entries it showed per project
in `database_views/<SHA-256>` (`DatabaseSession::viewState()`), and the page
of the last one in `database_page`. The event window keeps what it showed
of each event in `event_views/<SHA-256>/<map>/<event>` (`EventWindow`), its
size and the width of the page settings. An explicit navigation target (Search
opening an entry, an event at a page) overrides what was kept.

Presentation state must never serialize edited game values, undo history or
clipboard contents. `Reset local state` (`EditorSettings::resetLocalState()`)
removes the stored presentation state, puts open windows back to their first
size, centered, and the main window back to its default view, without saving
what they show meanwhile (`local_state_resetting`). Unsaved game edits and
preferences remain intact. A new settings key of presentation state goes in
the list it removes.
